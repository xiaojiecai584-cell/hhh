# Lindoway 手机端框架 · 技术方案

> 版本 v0.1（方案稿）｜ 阶段目标：手机端框架 —— 蓝牙双向收发 + AI 接口留白（人工输入）+ 等比例人体模型 + 标准动作实时演示

---

## 1. 范围与目标

本阶段只做「框架」，交付四件事：

1. **蓝牙双向收发**：手机 ↔ 硬件（MSPM0G3507 + JY61P + BLE 透传）通信，下发动作参数、接收事件包。
2. **AI 拓展接口留白**：定义 `Analyzer` 抽象接口，当前用人工输入实现，未来无缝替换为大模型。
3. **等比例人体模型**：根据用户录入身体数据，还原比例正确的人体模型。
4. **标准动作实时演示**：播放预设/自由输入的标准动作；当前预设两个动作 —— 坐姿推举、站姿侧平举。

---

## 2. 技术栈

- **应用形态**：PWA（免安装，扫码即用），Vite 构建。
- **框架**：React + TypeScript。
- **状态**：Zustand。
- **3D 渲染**：Three.js（参数化胶囊骨架人体）。
- **蓝牙**：Web Bluetooth API，通过 `BLETransport` 抽象隔离，未来可替换为 Capacitor 原生蓝牙覆盖 iOS。
- **样式**：手写 CSS / CSS Modules + 主题变量（运动简约风），不引重型 UI 库。

> iOS 说明：Safari 不支持 Web Bluetooth。本阶段以 Android Chrome/Edge 为主要演示环境；架构上蓝牙层已隔离，后续可用 Capacitor 补 iOS 原生通道。

## 4. 蓝牙协议（草案 v0.1）

> 与硬件固件对齐前，先定一版参考协议；协议层独立，字段可改。内置「虚拟设备」模拟整套交互。

### 4.1 BLE 服务

- 透传串口模块典型 UART 服务：Service `0xFFE0`，写特征 `0xFFE1`，通知特征 `0xFFE1`。
- UUID 走配置项，默认上述值，可针对真实模块调整。

### 4.2 下发指令（手机 → 设备），定长 10 字节

| 字节 | 字段 | 说明 |
|---|---|---|
| 0 | 帧头 | `0xAA` |
| 1 | CMD | `0x01` 开始会话 / `0x02` 停止 / `0x03` 下发动作参数 / `0x04` 校准归零 / `0x05` 心跳 |
| 2 | 动作ID | `0x01` 坐姿推举 / `0x02` 站姿侧平举 / `0x00` 无 |
| 3 | 主运动轴 | 1=肩屈(前举) 2=肩外展(侧举) 3=肘屈伸 |
| 4–5 | 峰值角度 | uint16，0.1° 精度，小端 |
| 6 | 腕部容限角 | 允许腕部翻转容差（°） |
| 7 | 建议节律 | 次/分钟（0=自由） |
| 8 | 行程下限 | 起始角度（°） |
| 9 | 校验 | 前 9 字节异或 |

### 4.3 回传事件包（设备 → 手机），定长 12 字节

| 字节 | 字段 | 说明 |
|---|---|---|
| 0 | 帧头 | `0xBB` |
| 1 | 事件类型 | `0x01` 动作完成 / `0x02` 实时报警 / `0x03` 心跳 |
| 2 | 动作ID | |
| 3 | 代偿标志位 | bit0 腕部翻转 / bit1 行程不足 / bit2 借力甩动 |
| 4–5 | 峰值角度 | uint16，0.1° 精度 |
| 6–7 | 动作耗时 | uint16，0.01s |
| 8 | 节律 | 次/分钟 |
| 9–10 | 保留 | 向心/离心时间比等 |
| 11 | 校验 | 前 11 字节异或 |

## 5. 数据模型

```ts
// 身体数据（等比例缩放输入）
interface BodyProfile {
  heightCm: number;
  weightKg: number;
  shoulderWidthCm: number; // 肩宽
  upperArmCm: number;      // 上臂长
  forearmCm: number;       // 前臂长
  torsoCm: number;         // 躯干长
}

// 关节角（度）
interface JointAngles {
  torsoFlexion: number;      // 躯干屈（前倾 +）
  shoulderFlexion: number;   // 肩屈（前举 +）——矢状面抬臂
  shoulderAbduction: number; // 肩外展（侧举 +）——额状面抬臂
  elbowFlexion: number;      // 肘屈
  hipFlexion: number;        // 髋屈（前抬腿 +）
  kneeFlexion: number;       // 膝屈
}

// 肩外展带来的大臂自然外旋（耦合近似，见 7.2）
// twist = clamp(abduction, -90, 90)
// 肩旋转 = Rz(外展) ∘ Rx(屈) ∘ Ry(外旋)，左臂取外展/外旋的镜像（取负）

// 动作关键帧
interface Keyframe {
  t: number;              // 归一化时间 0..1
  angles: JointAngles;
  easing: 'linear' | 'smoothstep';
}

// 动作模板
interface MotionTemplate {
  id: string;
  name: string;
  type: 'preset' | 'custom';
  mainAxis: 1 | 2 | 3 | 4 | 5; // 1肩屈 2肩外展 3肘屈 4髋屈 5膝屈
  peakAngleDeg: number;    // 峰值角度
  wristToleranceDeg: number;
  cadence: number;         // 节律 次/分
  durationMs: number;      // 单次时长
  keyframes: Keyframe[];
}

// 事件包
interface EventPacket {
  type: 'complete' | 'alert' | 'heartbeat';
  actionId: number;
  flags: { wristFlip: boolean; shortRange: boolean; momentum: boolean };
  peakAngleDeg: number;
  durationMs: number;
  cadence: number;
}

// 会话报告（供报告引擎 + Analyzer 使用）
interface SessionReport {
  actionId: number;
  events: EventPacket[];
  totalReps: number;
  complianceRate: number;
  compensationCount: number;
}

// AI 分析结果（人工输入与未来 AI 同构）
interface AnalysisResult {
  score: number;      // 0–100
  summary: string;
  advice: string[];
  anomalies: { label: string; detail: string }[];
}
```

## 6. 等比例人体模型（Three.js）

- 用 **Group 层级 + 胶囊体** 拼装（不用蒙皮权重），每个关节是一个 pivot Group，旋转即绕关节转。
- 骨骼层级（上半身重点，下半身简化）：

```
root(髋) → 躯干 → 头
躯干 → 左肩 → 左上臂 → 左肘 → 左前臂 → 左手
躯干 → 右肩 → 右上臂 → 右肘 → 右前臂 → 右手
root → 左髋 → 左大腿 → 左膝 → 左小腿 → 左足
root → 右髋 → 右大腿 → 右膝 → 右小腿 → 右足
```

- 等比例：各段骨骼长度由 `BodyProfile` 驱动；缺失字段按身高比例估算。
- 皮肤：低多边形胶囊体 + 哑光材质，深色底 + 荧光强调色点缀，符合运动简约风。
- 视角：可旋转/缩放（OrbitControls），演示时默认侧后 45° 观察主运动面。

## 7. 动作引擎与实时演示

### 7.1 关键帧插值

- `MotionPlayer`：给定 `MotionTemplate`，按 `t` 在相邻关键帧间插值，`smoothstep` 缓动，输出当前 `JointAngles`。
- 控制：play / pause / seek / loop / 倍速。

### 7.2 肩关节几何（通用约束，任何动作都适用）

模型里「肩屈」与「肩外展」是两条正交的抬臂通路，肘的弯曲平面又由大臂朝向决定，因此组合不对就会渲染出完全错误的姿势：

| 目标 | 正确参数化 | 错误做法 |
|---|---|---|
| 手臂在身体正前方抬起（前平举/推/俯卧撑支撑） | 只用 `shoulderFlexion`，`shoulderAbduction = 0` | — |
| 手臂在身体两侧抬起（侧平举/推举/投降状） | 只用 `shoulderAbduction`，`shoulderFlexion = 0` | 用 `shoulderFlexion` 近似侧向动作 → 变成前平举，手跑到脸前方 |
| 双手在肩两侧、前臂竖直向上（投降状/推举准备位） | `shoulderAbduction = 90` + `elbowFlexion = 90` | — |
| 双臂过头伸直（推举顶点） | `shoulderAbduction = 180` + `elbowFlexion = 0~10` | 用 `shoulderFlexion` 90→180 → 先变成前平举 |

要点：

- **肘屈只能绕大臂自身的局部轴弯曲**，所以「大臂侧平 + 屈肘」在纯三自由度模型下数学上做不出来（前臂只会在水平面里前后摆）。真实人体靠肱骨外旋（掌心朝前）实现，模型上用**耦合近似**补上：外展多少就外旋多少，封顶 ±90°（`shoulderTwistDeg`）。这一步是通用的，不是针对某个动作的特判。
- 侧平举时同一套耦合也让前臂从「略前屈」自然过渡到「额状面内」，不会出现关节跳变。
- 正向运动学在四个地方实现，必须保持一致：`pose.ts`（demo 骨骼）、`kinematics.ts`（IMU 目标）、`groundContact.ts`（地面接触解算）、`server/skeleton.mjs`（视觉评审渲染）。`scripts/verify-pose.mjs` 会随机扫 7000 组关节角比对四条路径的方向向量（实测偏差 ~2e-6 度）。

### 7.3 两个预设动作（关键帧为示例，可后调）

**坐姿推举**（主运动轴 = 肩外展）：

| t | 肩外展 | 肘屈 | 备注 |
|---|---|---|---|
| 0.0 | 90° | 90° | 起始：上臂侧平、前臂竖直向上，双手在肩两侧（投降状） |
| 0.5 | 180° | 5° | 推举至头顶上方，手臂伸直 |
| 1.0 | 90° | 90° | 回到起始 |

**站姿侧平举**（主运动轴 = 肩外展）：

| t | 肩外展 | 肘屈 | 备注 |
|---|---|---|---|
| 0.0 | 0° | 15° | 起始，手臂自然下垂 |
| 0.5 | 90° | 15° | 侧举至与肩同高 |
| 1.0 | 0° | 15° | 回到起始 |

### 7.4 实时演示画面

- 3D 模型动画 + 同步「关节角-时间」曲线（Canvas 绘制，光标指示当前时刻）。
- 主运动轴角度曲线高亮；同时展示峰值角度/容限参考线。

### 7.5 自由输入标准动作（关键帧参数输入）

- 新建自定义动作：输入主运动轴、峰值角度、腕容限、节律、单次时长；编辑起止/中间关键帧（躯干屈、肩屈、肩外展、肘屈、髋屈、膝屈）。
- 即时预览播放，可存为自定义模板，与预设动作同等待遇（可演示、可下发）。

### 7.6 界面分两套入口（一份代码）

同一个站点、同一份代码，用 URL hash 区分两套界面，避免两份实现随时间长歪：

| 入口 | 面向 | 标签页 | 内容 |
|---|---|---|---|
| `https://<站点>/` | 用户 | 训练 / 动作 / 演示 / 报告 / 我的 | 只有：设备状态、选动作、目标次数、大号计数与计时、一个「开始 / 结束」按钮 |
| `https://<站点>/#/debug` | 开发调试 | 训练 / 数据 / 仓库 | 额外保留：设备类型切换（虚拟设备）、BLE 参数（服务/写/通知 UUID 地址）、指令下发日志、实时姿态原始值、动作录制与标注、事件回传（0x02）、接收原始帧（十六进制） |

- 用 hash 而不是路径，是为了不依赖服务端 SPA 回退配置。
- **主界面不出现任何 UUID / 地址 / 十六进制帧**，那些只在调试站里。
- 默认传输层是真机（Web 蓝牙）；虚拟设备只作为调试工具存在于调试站。
- 「中途停止」与「达标停止」下发**同一条** `0x83`，不做区分；停止原因只记在本地，
  以便将来区分「做满一组」和「中途放弃」的样本。

## 8. AI 接口（人工输入替代）

```ts
interface Analyzer {
  analyze(report: SessionReport): Promise<AnalysisResult>;
}
```

- 当前实现 `ManualAnalyzer`：报告页提供人工填写 —— 评分滑条、结论文本框、建议列表（可增删 + 常见建议模板一键插入）、异常项标注。
- 产物为 `AnalysisResult`，与未来 AI 输出同构；报告渲染不区分来源。
- 未来接大模型：新增 `LLMAnalyzer` 实现即可，UI/报告层零改动。

## 9. UI 与流程

- 风格：深色底 + 高饱和荧光强调色（荧光绿/橙）、大号数字、卡片式布局、大触控按钮、底部 Tab 导航。
- 流程引导式：**连接 → 录入身体 → 选动作 → 开始演示 → 看报告**。

页面（底部 Tab）：

1. **连接**：蓝牙扫描/连接、连接状态机、虚拟设备开关。
2. **身体**：身体数据录入 + 人体模型实时预览。
3. **动作**：动作库（2 预设 + 自定义）+ 关键帧编辑器。
4. **演示**：3D 模型 + 关节角曲线 + 播放控制 + 实时事件/报警提示。
5. **报告**：事件列表 + 达标率/代偿统计 + 人工分析输入。
